## 一、功能现状

当前系统**只有后端 API**（Gin 服务，`cmd/api/main.go`），没有任何前端页面。所有能力（登录 / 会话 / 对话 / 文档 / 工具配置 / 用量）都只能靠 curl 或 Postman 调用，无法作为 SaaS 产品演示。

## 二、前端方案（已与需求方确认）

### 2.1 技术选型（极简方案，零构建）

| 技术 | 选型 | 理由 |
|------|------|------|
| 框架 | 纯 HTML + 原生 JS | 不引入 React/Vue，部署简单、好调试 |
| 样式 | Tailwind CSS CDN | 不用本地构建，直接 CDN 引入 |
| 图标 | Font Awesome CDN | 图标够用 |
| 打包 | 无构建 | 静态文件直接扔 Nginx |
| 交互 | fetch API + 原生 DOM | 不用 axios |

### 2.2 页面结构（3 个页面）

1. **login.html**：登录（用户名+密码）+ 租户注册（创建租户+管理员），居中卡片、tab 切换。
2. **index.html**：三栏主工作台
   - 顶栏：租户名 / 用户名 / 角色 / 管理入口（仅 admin 可见）/ 退出
   - 左栏：会话列表（新建 / 点击切换 / 删除）
   - 中栏：对话消息流（用户右、AI 左）+ 输入框；展示工具调用过程（可选加分项）
   - 右栏：文档管理（拖拽/点击上传、文档列表、状态轮询、删除）
3. **admin.html**：管理后台（仅 admin 可见入口）
   - 工具开关配置（`GET/PUT /api/admin/tool-config*`）
   - 用量统计（当天 + 最近 N 天）

> **本轮不做用户管理**（需求方已确认）：后端无管理员创建用户接口，admin 页只做工具配置 + 用量统计。

### 2.3 鉴权与 API 封装

- 登录成功把 JWT 存 `localStorage`，每次请求带 `Authorization: Bearer <token>`。
- `api.js` 统一封装：`res.status === 401` → 跳登录页；**业务错误（HTTP 200 + `body.code !== 0`）也要判断**（本项目业务错误统一 HTTP 200 + code 区分，见「接口支撑对照」第 6 条）。
- 登录后缓存 `user`（username / tenant_id / role）与租户名到 localStorage，页面刷新免重复拉取。

## 三、登录体验改造（后端配合，需求方已确认）

需求方要求：**登录只输用户名 + 密码，不输 tenant_id 也不输租户名**。当前 `POST /api/user/login` 的 `tenant_id` 是 `binding:"required"`，必须调整。

### 3.1 后端改动

**1. `LoginReq.TenantID` 改为可选（`api/handler/user.go`）**

```go
type LoginReq struct {
	TenantID uint64 `json:"tenant_id" binding:"omitempty"`            // 可选：传了则按租户+用户名查；不传按用户名全局登录
	Username string `json:"username" binding:"required,min=2,max=64"`
	Password string `json:"password" binding:"required,min=6,max=128"`
}
```

**2. `service.Login` 支持"用户名全局登录"（`api/service/user.go`）**

- `tenantID > 0`：保持现状（按租户 + 用户名查，兼容老调用方）。
- `tenantID == 0`：按用户名全库查询（新增 `storage.FindUsersByUsername`）：
  - **恰好 1 个用户** → 直接登录（签发 JWT 用该用户的 tenant_id）；
  - **多个用户** → 返回明确错误「该用户名在多个租户下存在，无法自动登录，请提供租户 ID」；
  - **0 个** → 统一「用户名或密码错误」（不区分用户不存在/密码错误，防探测，延续现状）。

> ⚠️ 边界说明（已与需求方确认方案）：`users.idx_tenant_user` 联合唯一索引决定**不同租户可共存同名用户**（README 实测"租户 A/B 可共存同名 admin"）。纯用户名登录遇到同名冲突无法消除歧义，只能返回错误引导——这是该方案的固有边界，需求方接受。

**3. 登录 / 注册响应脱敏（`storage/model/models.go`）**

- `User.PasswordHash` 加 `json:"-"`：登录、注册、注册租户等接口返回 `user` 对象时不再泄露密码哈希（README 红线：敏感信息不外泄）。
- 其余字段（ID/TenantID/Username/Role/Status/时间）不受影响。

**4. 新增 `storage.FindUsersByUsername`（`storage/user.go`）**

```go
// FindUsersByUsername 按用户名全库查询（可能命中多个租户的同名用户）
func FindUsersByUsername(ctx context.Context, username string) ([]model.User, error)
```

### 3.2 前端适配

- login.html 登录表单只有「用户名 + 密码」两个输入框；提交 `POST /api/user/login` **不传 tenant_id**。
- 同名冲突时后端返回 400 明确错误，前端 toast 展示该提示（此时用户可改用租户注册页重新注册唯一用户名，或由管理员处理）。
- 注册页：`POST /api/tenant/register` 成功后**不返回 token**，前端自动用刚注册的 admin 账号调一次登录完成免手工输入。

## 四、前端页面设计

### 4.1 文件结构（`web/` 新增目录）

```text

├── admin.html       # 管理后台

    ├── chat.js      # 会话列表 + 对话逻辑

    └── admin.js     # 工具开关 + 用量统计
```

### 4.2 index.html 交互细节

| 区域 | 交互 | 后端接口 |
|------|------|---------|
| 顶栏 | 登录后调 `GET /api/tenant/:id` 拿租户名（登录响应 user 只有 tenant_id）；admin 显示「管理后台」入口 | `GET /api/tenant/:id` |
| 左栏 | 新建会话 `POST /api/session`；列表 `GET /api/session/list`；切换会话加载历史 `GET /api/session/:id/messages`；删除 `DELETE /api/session/:id` | 见左 |
| 中栏 | 发送 `POST /api/chat`（携带当前 session_id，空则后端自动建会话）；工具调用过程展示：chat 响应 `tool_calls` 只有工具名，发送后**再刷新一次历史接口**拿到 `kind=tool_call/tool_result` 的完整过程 | `POST /api/chat` + `GET /api/session/:id/messages` |
| 右栏 | 上传 `POST /api/document/upload`（FormData 字段 `file`）→ 拿 `task_id` 轮询 `GET /api/task/:id`（间隔 2s，防撞限流）→ 完成后刷新列表；列表 `GET /api/document/list`；删除 `DELETE /api/document/:id` | 见左 |

> ⚠️ 已知限制（实现时前端做提示，不属本轮后端改动）：
> - **删除文档仅上传者本人可删**（用户级隔离）：member 删他人文档返回 400「无权删除他人文档」，前端删除按钮对非本人文档置灰或失败 toast。
> - **无流式输出**：后端 chat 为普通 JSON 全量返回，前端等待完整回答后渲染。
> - **限流**：用户级 60 次/分、对话级 20 次/分；任务轮询间隔 ≥2s，避免高频轮询撞 429（429 时退避重试）。

### 4.3 admin.html 细节

| 区域 | 交互 | 后端接口 |
|------|------|---------|
| 工具配置 | 渲染开关列表（`tool_name / is_enable / description`），toggle 调 `PUT /api/admin/tool-config/:tool_name` | `GET /api/admin/tool-config`、`PUT ...` |
| 用量统计 | 当天 `{tokens, calls}` + 最近 7 天表格（`GET /api/admin/usage/history?days=7`），可用简单 CSS 柱状条 | `GET /api/admin/usage/today`、`GET /api/admin/usage/history` |

### 前端需特别注意的后端约定

1. **统一返回结构**：`{code, message, data}`；成功 `code=0`、HTTP 200。业务错误（400/403/500）**HTTP 200 + code 非 0**；仅鉴权失败（401）是真正 HTTP 401。`api.js` 必须同时判断 `res.status === 401` 与 `data.code !== 0`——401 时登录接口的服务器 message（如"多租户同名"）会透传给前端展示，业务页面的 401 才跳登录。
2. **403 语义**：`response.Forbidden` 走 HTTP 200 + code=403（如越权访问他人会话）。
3. **会话标题**：`POST /api/session` 可不传 title（默认「新会话」）；chat 接口空 `session_id` 自动建会话，标题取首问前 20 字。
4. **文档删除用户级隔离**：仅上传者可删。
5. **限流**：全局限流（租户 300/分、用户 60/分）+ 对话专属（20/分）+ 配额拦截；429 触发需退避。

## 九、上线前注意

- 前端为纯静态文件：`web/` 目录整体挂载到 Nginx，`/api` 与 `/health` 反代到后端 `SERVER_HTTP_PORT`（默认 8080）。
- 登录接口 `tenant_id` 变可选后**向后兼容**：老调用方（e2e 脚本）继续传 tenant_id 行为不变。
- `User.PasswordHash` 加 `json:"-"` 后所有返回 user 的接口自动脱敏，无字段名变化（前端不读该字段）。
- CORS：`cors.Default()` 允许任意来源，开发期前端不同端口可直连；生产走 Nginx 同源反代后 CORS 不涉及。
